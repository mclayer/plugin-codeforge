**Runtime hook dispatcher 계층 경계** (ADR-115 / ADR-061 / CFP-2965): harness 가 발화하는 훅은 **3층**으로 분리된다 — **L1 dispatcher** (`hooks/run-hook.cmd` polyglot single-file: Unix 는 line-1 `exec bash`, Windows 는 cmd.exe 배치 본문 → Git-Bash 위임. bash 부재 시 `exit /b 0` fail-open) · **L2 thin wrapper** (`hooks/<name>` 셸 — bypass env audit · payload 수령 · 인터프리터 해소 `python3 → python → exit 0`) · **L3 판정 SSOT** (`scripts/lib/*.py` — 실제 deny/inject 판정). 경계 규율: L2 는 판정 로직을 갖지 않고(ADR-061 thin wrapper), L3 는 harness 계약(exit 0/2)만 방출하며, L1 은 종료 코드를 변형 없이 전파한다(괄호 블록 `%ERRORLEVEL%` parse-time 확장 금지 — 평탄화 시 deny 소실). 훅 간 관계는 **sibling disjoint** (ADR-115 §결정 3): 4 deny-gate + 1 injection 이 서로의 판정 표면을 읽지 않으며, `updatedInput` single-writer 는 injection 훅 1개뿐이다.

**게이트 결정론의 시간 예산 경계 (timeout fail-open)** (ADR-115 Amendment 2 / CFP-2965): 훅 판정은 무한 시간 안에서 결정론적인 것이 아니라 **명시 시간 예산 안에서만** 결정론적이다. `hooks/hooks.json` 의 26 leaf handler 는 각자 `timeout`(초, 값 공간 {1,5,10,15,30,60})을 선언하며, 만료는 **플랫폼-강제 fail-open**(해당 훅만 취소 + tool call 진행)이다 — 즉 "게이트가 켜져 있음"은 "예산 안에 판정이 끝났음"과 동치이고, 부하가 높을수록 게이트가 꺼질 확률이 커지는 **로드 상관 잔여 리스크**가 구조적으로 남는다(완화 불가 declare). 이 경계에서 파생되는 설계 규칙 3종: ① **하한 불변식** — 훅 timeout ≥ 내부 subprocess 예산 합 + 기동 여유 (예: 네트워크 훅의 gh 누적 예산 `GH_TOTAL_BUDGET_SEC=50` < timeout 60) ② **fail-open 계상 의무** — 값 결정은 "만료 1회 손실 심각도 × 만료 확률" 2축으로 산정하고 손실을 문서에 남긴다 ③ **차등 tier** — 균일값 금지(advisory·record-only 는 최단, 비가역 손실 게이트는 최장). 예산을 내부 로직으로 bound 하면 만료(무흔적 kill)가 **내부 fail-open(진단 stderr 1줄 + 흔적)** 으로 전환되어 관측성이 올라간다.

**Consumer merge-gate boundary** (ADR-132 / CFP-2469): consumer repo 의 게이트 강제력 = **2-layer** — (a) advisory hook 層 (UserPromptSubmit warning-inject-only, block 아님) ↔ (b) mechanical branch protection 層 (GitHub native `required_status_checks` merge 실차단). dead-gate(게이트 workflow 가 PR 마다 돌지만 `required_status_checks.contexts[]` 미등록 = merge 차단력 0) 해소 = mechanical 層 자동 충전 (`scripts/wire-branch-protection.*` operator gh auth GET-merge-PUT). 권한 경계: 자동 배선 = operator org-admin gh auth (codeforge PAT 미사용 — ADR-066 §결정 2 6-scope 무손상). 형상: `enforce_admins:true`(admin 우회 무력화 차단) + `review_count` solo=0/team≥1(deadlock 회피). 등록 context set = consumer 실제 배포 workflow job 표시명 ∩ codeforge 게이트(정적 manifest 복사 금지 — wrapper-self context 영구 pending 차단).

**수령 사실(receipt)의 기록 authority 경계** (ADR-139 Amendment 3 / ADR-170 Amendment 2 / CFP-2994): 기록 authority 는 **객체에 따라** 갈린다 — **verdict**(성과·liveness 판정)은 산출물·marker·rc 로 타자 검증이 가능하므로 lead 에 고정되고(ADR-139 INV-L4 — INV-L1~L4 및 §결정 1~7 무변경), **수령 사실**(통지·핸드오프 도달)은 상대 inbox 를 열거할 수단이 없어 타자 검증이 물리적으로 불가하므로 **수신 주체 단독 발행**이다. 두 객체는 disjoint 이며, 후자는 INV-L4 의 예외가 아니라 **그 정의역 밖 신설 entry** 다(약화 방향 없음 — ADR-064 §결정 7 symmetric ratchet 상 강화). 파생 규율: 수령 상태 표기(`receipt_state`)는 **도달(arrival) 전용** 경계 — 산출물 존재·귀속 기록은 허용하되 **충분성·품질·채택 가치 판정은 금지**(그 판정은 lead 잔존). 기록 귀속 위반 분류는 ADR-170 Amendment 2 가 저작 ⊥ 전사 축에 「타 주체 저작을 흡수하며 귀속을 자기로 표기」 형태를 추가해 확장한다(§결정 2 inline whitelist enumeration 무변경 — entry 신설·축소 없음).

**신뢰 밖 입력 × 신뢰 안 환경 신뢰경계 (ADR-172 / CFP-2949)**: 세션 독립 로컬 스케줄 작업 도입으로 codeforge 에 **신뢰 밖 입력(PUBLIC repo 의 외부 저작 텍스트)을 신뢰 안 환경(운영자 홈)에서 처리하는 최초 노드**가 생긴다. 지금까지 모든 기계 주체(GitHub Actions 러너)는 신뢰 밖 입력을 **신뢰 밖 환경**에서 처리했다 — 신뢰경계와 실행경계가 일치했고, 본 노드에서 그 일치가 깨진다(권한면 6종을 주입이 아니라 **상속·누적**). **도입기 완화 2축**: (a) 읽는 표면을 **코멘트 메타데이터 + 자기 마커 라인**으로 한정 (b) reconcile·dedup·마커·발화를 **결정론 CLI**(`scripts/lib/scheduled_task_reconcile.py`)에 귀속시켜 LLM 재량 축소. **정직 라벨**: 잔여가 남으며 **완전 차단은 불가**하다 — 이 형상에서 플랫폼 안티-인젝션 4종이 전건 무력하고(ADR-172 결과 5), 상속 자격증명은 회수 불가이며 채널 write 축은 도구층 `deny` 정의역 밖이다(결과 6·10). branch protection 8-tuple 무변경.
