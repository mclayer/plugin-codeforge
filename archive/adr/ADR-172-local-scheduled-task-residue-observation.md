# ADR-172: 로컬 스케줄 작업 기반 세션-독립 잔재 관측 — 도입기 관측-only 와 승격 게이트

## 상태

Accepted (2026-08-13) — CFP-2949 Phase 1(설계) carrier.

## 컨텍스트

codeforge 의 로컬 잔재 수렴(worktree eager teardown · residue-clean · scratch TTL · orphan 판정)은 **Orchestrator 자율준수에 의존**한다. required CI 로 승격할 수 없는데, 그 이유가 구조적이다 — 잔재 스캔 대상(`~/.claude/worktrees` · `~/.claude/codeforge-scratch` · workspace root · Temp)이 **운영자 홈에 결박**돼 있고 GitHub Actions 러너에는 그 홈이 존재하지 않는다. ADR-128 은 이를 "단일 자동 수렴 검증기 **구조적 불가**"로, ADR-169 는 잔여 4클래스(crash 미발화 · advisory ceiling · fail-safe 보수성 · per-repo 협소)로 각각 박제했다.

여기에 **세션과 독립적으로 운영자 머신에서 세션을 자동 개시하는 실행 surface**(Claude Desktop 로컬 스케줄 작업)가 등장했다. 이 surface 는 로컬 FS 도달 · 최소 간격 1분 · 세션 독립을 **동시에** 만족하는 유일한 축이다(Actions 는 로컬 미도달, 관리 클라우드·self-hosted 는 운영자 홈이 기본 구성 밖).

동시에 이 surface 는 codeforge 에 **신뢰 밖 입력을 신뢰 안 환경에서 처리하는 최초 노드**를 도입한다. 지금까지 모든 기계 주체(Actions 러너)는 신뢰 밖 입력을 신뢰 밖 환경에서 처리했다. 스케줄 작업 세션은 운영자 머신에서 사람 없이 개시되며 권한면 **6종**을 **주입이 아니라 상속·누적**한다 — 5종은 세션 시작 시점에 host 설정·인증 상태로부터 **상속**되고, 1종(태스크별 저장 승인 "Always allowed")은 운영자의 1회 승인이 이후 전 run 에 영구 적용되며 **누적**된다.

실행 surface 선택은 2026-08-12T12:15:00+09:00 사용자 결정이며, 그 지위는 **가치 판단**이다(배제된 축들은 "도달 불가"라는 사실 주장이 아니라 비용·위험 판단으로 범위 밖).

## 결정

### §결정 1 — 채택 surface 와 도입 곡선

로컬 스케줄 작업을 채택하되 **도입기는 관측-only** 로 고정한다. 산출은 `선언값 · 실측값 · 불일치` **사실 3-tuple** 이며, `PASS`/`FAIL`/`OK`/`정상`/`문제없음` 같은 **verdict 어휘가 등장하면 그 순간 ADR-106 의 "판정" 단계에 진입**해 기결정을 위반한다. 하위 스크립트 출력에 verdict 어휘가 있으면(실측 오염원 1건 존재) **그 줄은 인용하지 않고 수치 필드만 재서술**한다.

**1호 대상 = 로컬 잔재 관측 보고 1종.** 3필터(주기 ≥1분 ∧ 실행 예산 ∧ 로컬 FS 도달) AND 통과 ∧ 기존 workflow 116개와 중복 0(그 0 은 구조적 — Actions 러너에 운영자 홈이 없어 해당 workflow 가 작성될 수 없다).

### §결정 2 — 정본 SSOT 무손상, 저장 프롬프트는 부트스트랩

절차 정본은 **기존 skill** 이다. 저장 프롬프트는 절차를 **0줄** 담고 정본을 지목만 한다. 정본 미도달 시 fallback 은 **정직 중단**이며 **경로 하드코딩은 금지**한다(정본 이동 시 조용히 stale 해져 hollow 가 된다). 정본 skill 에 "스케줄 작업 인지 분기"를 넣는 **역참조를 금지**한다(현재 정본 2종에 관련 리터럴 0건이며 이 0 을 불변식으로 유지).

부트스트랩 프롬프트 전문은 **본 ADR 에 박제**한다 — repo 신규 지시 파일을 만들지 않으면서 프롬프트 축의 버전관리·리뷰를 성립시키는 유일한 자리다.

```
codeforge 로컬 잔재 관측 (관측-only · 보고 전용)

1. <repo 절대경로> 로 cd 한다. 작업 디렉터리 설정에 의존하지 않는다.
2. codeforge:worktree-lifecycle skill 의 잔재 관측 절차를 정본으로 읽는다.
   정본을 찾지 못하면 "정본 미도달" 을 사실로 보고하고 즉시 종료한다.
   절차를 기억이나 추측으로 대체하지 않는다.
3. scripts/lib/scheduled_task_reconcile.py 를 실행한다.
   이 CLI 가 채널 조회·중복 제거·마커 부착·보고 채널 발화까지 전부 수행한다.
4. 보고 채널에 직접 쓰지 않는다. CLI 산출의 수치 필드만 인용해 실행 결과를 확인하고,
   실패·미도달이면 그 사실만 보고하고 종료한다.

금지: 파일 삭제·이동·worktree 제거·stash drop / GitHub label·state·merge·close 변경 /
      보고 채널에 직접 코멘트 작성 / 보호 브랜치 push / 자기 스케줄·프롬프트 수정 /
      하위 출력의 verdict 어휘 인용.
이 작업은 관측하고 보고만 한다. 판정도 집행도 하지 않는다.
```

### §결정 3 — 정의 거버넌스: two-master 는 **잔존한다**

프롬프트 축은 §결정 2 로 git-resident 가 되지만, **등록 축(schedule · folder · model · enabled · permission mode)은 git 으로 재현할 수 없다.** 등록 상태를 repo 에 미러하는 선언 파일은 **도입하지 않는다** — 등록 상태를 기계 판독할 표면이 없어 **drift 대조 수단이 없고**, 대조 불가능한 미러는 버전관리의 외형만 만들고 실질을 주지 않는다.

⇒ **`[git-재현-불가: 등록 축]` 으로 라벨하고 수기 절차로 인정한다. "two-master 없음" 이라고 쓰지 않는다.**

### §결정 4 — 관측-only 의 기계 lever 와 **계상 금지 조건**

기계 강제는 두 층에서만 성립한다.

1. **스크립트 층 3중 게이트** — `mode`=observe-only(삭제 코드경로 미진입) ∧ `GC_DRY_RUN=1`(실 삭제 직전 분기) ∧ `TEMP_GC_DELETE_ENABLED` unset. **신규 플래그 0건.**
2. **권한 층** — `permissions.deny` 키 신설(전 모드에 적용되는 유일 통제이며 **현재 키 부재**) + per-task permission mode `Manual` 고정 + `disableBypassPermissionsMode`.

**host `~/.claude/settings.json` 을 방어 lever 로 계상하지 않는다** — 실측이 `allow` 40건 · `deny` 키 부재 · `defaultMode: bypassPermissions` 이므로 **넓히는 방향으로만 작동하며 제한 기여가 0** 이다. 제한 기여 0 인 항목을 lever 로 세는 것 자체가 검사연극이다.

★ **계상 금지 조건**: 위 권한 층은 **각 lever 의 실효성을 스케줄 작업 세션에서 live 실측하기 전까지 lever 로 계상하지 않는다** — 3축 전건이 대상이다: (V1) `deny` 가 태스크 세션에 적용되는가 (V2) 태스크 permission mode 가 host `defaultMode` 를 상속하는가(상속하면 born-at-max-privilege) (V3) `disableBypassPermissionsMode` 가 user-scope 설정에서 실효하는가. 미실측 상태의 "안전하다"는 서술은 그 자체가 검사연극이다(ADR-119). **이는 어느 lever 가 무효라는 판정이 아니라, 판정 이전에 계상하지 말라는 요구다.**

### §결정 5 — reconcile 은 **상태 무의존**이고 **결정론 코드**다

플랫폼이 누락 실행을 회수할 때 **최근 1회만 실행하고 나머지는 폐기**하므로, 대상을 "이 tick 이 담당하는 구간"으로 정의하면 폐기된 tick 의 대상이 **영구 미관측**이 된다.

⇒ 대상은 `g(현재 상태)` 다. **매 실행이 현재 잔재 전량을 재관측**하고 상태를 이월하지 않는다. dedup 키는 `class + 홈-상대 경로` 로 **대상에서 유도**하며 저장하지 않는다(상태 파일을 두면 그 파일 자신이 잔재가 되는 자기참조가 생긴다). dedup 상태의 실질 저장소는 **append-only 보고 채널 자신**이며, 조회 실패는 **fail-closed**(다음 실행이 자기치유).

**이 reconcile·dedup·마커 부착·보고 채널 발화는 자연어 프롬프트가 아니라 결정론 CLI 에 둔다.** 프롬프트에 두면 검사 대상이 LLM 이 되어 해당 수용 기준들의 결정론 오라클이 붕괴하고, 그러면 그 기준들을 강등해야 하는데 강등 근거가 없다.

**★ 발화가 이 열거에 포함되는 것은 필수다.** 렌더에서 끊고 발화만 LLM 세션에 넘기면 (a) 발화 개체 수·중복 0·정지 시 무발화·조회 실패 fail-closed 를 검사하는 오라클 전건이 **확률적 대상**을 겨누게 되고 (b) LLM 이 마커를 **운반**하게 되어 "LLM 이 마커를 부착하는 형상은 비결정론이므로 불가" 라는 판정과 정면 충돌하며 (c) 세션의 채널 write 도구가 §결정 4 의 `deny`(`mcp__github__*` write)에 막혀 **태스크는 매 tick 돌지만 보고는 영원히 미착지하는 무음 사망**이 된다. ⇒ 발화 귀속은 본 결정의 **분리 불가 부분**이며, 그 대가는 결과 10 에 기재한다. 이는 §결정 2 의 "지시 파일 금지"에 저촉되지 않는다 — 금지 대상은 **절차를 서술하는 지시 파일**이지 **절차를 실행하는 코드**가 아니다.

### §결정 6 — 운영 파라미터 (전건 확정)

| 항목 | 값 | 근거 |
|---|---|---|
| 주기 | **Daily** | 실행 예산 소비 여부가 미확인이므로 보수 선택. 잔재는 누적형이라 저빈도에서 가치 손실이 작다 |
| worktree 격리 토글 | **OFF** | ON 은 실행마다 worktree 를 만드는데 **생성 위치·회수 주체가 둘 다 미확인**이다. 잔재 스캔 도메인에 생기면 매 보고가 자기 소음이 되고, workspace root 에 생기면 유일한 삭제 허용 root 에 자기 발밑을 넣는다. **미확인은 안전 근거가 아니다** |
| 작업 디렉터리 | **기존 main 체크아웃** | **INV-OBS: 관측자는 자기 관측 도메인에 새 객체를 추가하지 않는다.** 이미 존재하는 객체라 신규 0 |
| 긴급 정지 | **2-플래그 OR, fail-closed** | 기존 repo-resident 플래그는 **활성화에 커밋이 필요**해 즉시성이 없다. 신규 로컬 플래그를 **scratch 밖**(`~/.claude/worktree-gc-state/`)에 둔다 — scratch 에 두면 TTL purge 가 7일 뒤 **정지 장치를 조용히 삭제**한다 |
| 생존 감시 | **로컬 세션 시작 축 watchdog** — heartbeat 기록 주체·시점은 **결정론 CLI 의 정상 종료**로 고정 | 클라우드 역구조는 성립하나 **겨냥이 틀리다** — 승인 대기 정지와 앱 미상주를 구별할 정보가 없어 머신 오프 구간을 전부 오탐한다. **기록 주체는 결정의 load-bearing 부분이다** — 세션이 heartbeat 를 기록하면 CLI 를 기동조차 못한 실행도 fresh 기록을 남겨 watchdog 이 **구조적 false-negative**(관측자가 죽었는데 살아 있다고 보고)가 된다 |

> ★ **정정 포인터 (FIX9 추가) — 위 표 `생존 감시` 행(`:119`)은 후속 Amendment 로 두 축에서 좁혀졌다.** 위 표의 행은 **삭제·개작하지 않고** 이력으로 보존하며, 충돌 시 아래 Amendment 가 우선한다.

### §결정 7 — 선행 결정과의 관계

- **ADR-128 §결정 4 정의역 amendment 를 발의한다** — "구조적 불가"의 정의역을 **클라우드 평면**으로 좁히고 세션 독립 로컬 스케줄러는 그 정의역 밖임을 각주한다. 약화되는 통제 0(순수 정의역 명확화). **단 "기계 게이트 신설 과설계 금지" 조항은 무손상 유지** — 정의역을 좁힌 것이 새 게이트를 만들어도 된다는 허가가 아니다.
- **ADR-169 본문은 amendment 하지 않는다** — 본문에 "클라우드 러너" 표현이 없다(그 표현은 playbook 전용). playbook mirror 만 수정한다.
- **★ ADR-169 §결정 4 판례를 승계한다** — 그 결정은 **같은 문제 도메인(로컬 잔재 GC)에서 이미** OS 스케줄러를 "**opt-in 보조이며 주 트리거가 아님**"으로 격하했다. 본 ADR 의 도입기 관측-only 는 이 판례와 정합이나, **주 트리거·required 로 승격하려면 그 판례의 재검토가 선행 의무**다.

### §결정 9 — 승격 게이트 (조건 · 주체 · rollback 경로)

**승격 조건 8항** (1-7 = 원 판정 / ⑧ = Amendment 1 신설)

1. 도입기 연속 운용에서 **오보 0**

5. **"read-modify-write 부재" 전제 재검사** — 승격은 이 전제를 깬다

| **도입기(관측-only)** | **2종** | 고정 sentinel 1줄 `[scheduled-task-observe]` + 태스크·run 참조 trailer `[scheduled-task-run]`. 형식은 기존 관용 `[prefix] k=v` 를 상속한다(신규 형식 발명 0) |

★ **브랜치 prefix 가 도입기에 적용 제외인 사유 (load-bearing)**: 도입기에는 커밋·push 가 **0건**이라 브랜치 prefix 검사가 **검사 대상 부재로 vacuous pass** 가 된다. 3종을 뭉뚱그리면 **마커 검사 자체가 hollow** 해진다. 따라서 도입기 검사 대상은 **2종으로 못박고**, 브랜치 prefix 는 **브랜치·커밋이 실제로 생성되는 승격 이후에만** 적용 대상이 된다.

**부착 주체 = 결정론 CLI** (§결정 5). LLM 이 마커를 운반하지 않는다.

**승격 이력 = 0건** (도입기 상태).

**미확인 1건 (정직 기재)**: (나)·(다)가 **진행 중인 run** 을 중단시키는지는 **확인 불가**다 ⇒ "즉시 정지된다" 고 쓰지 않는다. 진행 중 run 에 대한 정지는 **정지 플래그 판독 시점**에 의존한다.

## 결과

**얻는 것**: ADR-169 잔여 4클래스 중 **1건(crash 미발화 = observer-death)** 에 대해, 세션과 독립된 관측자가 사실을 보고한다. 나머지 3건은 본 ADR 이 해소하지 않는다(advisory ceiling 은 승격 이후 영역, fail-safe 보수성은 orthogonal, per-repo 협소는 ADR-169 §결정 2 가 이미 독자 해소).

**치르는 것 (honest ceiling — 결함이 아니라 선언된 상한)**

1. **다른 운영자는 본 결정을 merge 하는 것만으로 아무것도 얻지 못한다.** 작업 정의가 repo 밖 이 머신 로컬 config 다. "자동화를 배포했다"는 서술은 과장이다.
2. **등록 축 two-master 잔존** (§결정 3).
3. **관측 공백에 절대 상한이 없다** — 앱 미상주와 승인 대기 정지 어느 쪽도 문서상 상한이 0 이다. "공백 ≤ X" 를 단정하지 않는다.
4. **무음 사망은 탐지되지 않는다** — 승인 대기 정지는 막힌 것이 도구 호출 자체라 **자기보고가 원리적으로 불가능**하다. watchdog 은 완화이며 **watchdog 의 watchdog 은 없다. 최종 backstop 은 사람이다.**
5. **prompt-injection 은 완전 차단 불가** — 이 형상에서 플랫폼 안티-인젝션 4종이 전건 무력하다(권한 시스템은 `bypassPermissions` 가 무력화하며 문서가 "prompt injection 에 대한 보호를 제공하지 않는다"고 명시, 컨텍스트 격리는 특정 도구 한정, 승인 전 검토는 무인 실행이 정의상 제거, VM 권고는 로컬 FS 도달이라는 채택 근거와 충돌). 완화는 읽는 표면 축소 + 재량 축소이며 **잔여가 남는다**.
6. **상속 자격증명은 회수 불가** — `deny` 는 도구층 차단이지 scope 축소가 아니다.
7. **명의 귀속의 근본 해소는 별도 identity 발급인데 그것은 "자격증명 주입 0" 원칙과 정면 충돌한다** — 진짜 trade-off 이며 본 ADR 은 마커 완화만 선택했다.
8. **비대화형 호출 계약은 문서 = advisory.** 기계 강제는 §결정 4 두 층에만 있다.
9. **플랫폼 계약은 벤더 소유이고 본 결정이 그 위에 서 있다 — 변경 감시 트리거가 0 이다.** 누락 실행 회수의 7일 창, 단일 catch-up 후 older 폐기, skip 사유 3형상, per-task permission 모델, 작업 프롬프트 파일 경로, 자기수정 도구명은 전부 **공식 문서가 서술하는 벤더 계약**이지 우리가 통제하는 불변식이 아니다. 특히 **이름·경로에 결박된 검사**는 벤더가 rename 하면 실패로 드러나지 않고 **조용히 항상 통과**한다(vacuous-pass). §결정 5 의 상태 무의존 설계가 catch-up 정책 변경에는 견고하지만 **그것은 의도된 완화가 아니라 다른 목적의 부수 효과**다. ⇒ 대응은 **승격 시점 재실측 1점**뿐이며 상시 감시는 없다.
10. **보고 채널 write(발화) 축의 도구층 기계 lever 가 0 이다.** §결정 5 가 발화를 결정론 CLI 에 귀속시킨 결과, 채널 write 는 python subprocess 안에서 일어나 **도구층 `deny` 의 정의역을 구조적으로 벗어난다** — 6번이 말한 "도구층 차단" 이 이 축에는 도달하지 않는다. 남는 통제는 (a) CLI 코드 자신의 결정론(명명 테스트가 검사) (b) 상속 자격증명 scope — **축소 불가** 둘뿐이다. **대안(세션이 발화)은 이 write 를 `deny` 정의역 안에 두지만 그 귀결은 통제된 발화가 아니라 4번의 무음 사망**이다. ⇒ 발견된 구멍이 아니라 **선택된 대가**이며 숨기지 않고 기재한다.

**승격은 본 결정의 범위 밖이다.** 본 ADR 이 정하는 것은 승격 게이트의 설계(조건 · 주체 = **사용자** · rollback 경로 3종)까지이며 승격 실행은 별 Story 다. 자동 승격은 금지된다.

## Amendment 1 (CFP-2949, 2026-08-14) — §결정 6 heartbeat 발화 조건을 "관측 사이클 완주"로 좁힘

> **본 Amendment 의 지위**: **새 결정이 아니라 문면을 자기 근거에 맞추는 정정**이다. §결정 6 본문 행과 "관련 파일" 서술은 **무편집 보존**하며, heartbeat 기록 조건에 한해 본 절이 그 문면을 대체한다.
>
> ★ **FIX9 추기 — 위 "무편집 보존" 의 지위 판정 (본문 대조 후)**: ① **사실 주장으로는 참이었다** — §결정 6 절과 「관련 파일」의 heartbeat 서술은 `origin/main` 대비 문언이 그대로임이 3-dot diff 로 확인된다. ② **그러나 본 ADR 자기 관례와는 어긋난다** — 같은 문서의 다른 정정 4건(Amd 2·3·4·5 지위 문단, A5-3 의 site 24 처분)은 불변식을 **"삭제 0"** 으로 쓰고 **예외 없이 정정 포인터를 함께 남겼다**. 홀로 **"무편집"** 이라는 더 센 말을 쓴 본 절만 포인터를 0개 남겼고, 그 결과 §결정 6 을 읽은 독자는 두 축에서 좁혀진 사실을 모른 채 옛 문면을 정본으로 읽었다(관계축 co-change 게이트가 참 양성으로 검출). ③ **본 FIX9 편집 이후로는 문자적으로도 거짓이다** — §결정 6 절 끝에 정정 포인터 블록이 추가됐다. ⇒ **처분**: "무편집" 의 정의역을 **본문 행의 문언(삭제·개작 없음)** 으로 한정하고 **정정 포인터 추가는 그 정의역 밖**임을 확정한다. 위 문장은 **삭제하지 않고 이력으로 보존**하며, 충돌 시 본 추기가 우선한다.

### A1-1 계기 — 문면과 자기 근거가 어긋난 채 구현됐다

Phase 2 구현리뷰 FIX iter1 에서, §결정 6 의 **문면**("heartbeat 기록 주체·시점은 **결정론 CLI 의 정상 종료**로 고정")과 **같은 결정의 근거문**이 어긋난 채 구현된 것이 드러났다.

근거문은 *"세션이 heartbeat 를 기록하면 **CLI 를 기동조차 못한 실행도 fresh 기록을 남겨** watchdog 이 **구조적 false-negative**(관측자가 죽었는데 살아 있다고 보고)가 된다"* 를 금지 사유로 든다. 그런데 **정지 플래그 감지 종료 경로가 스캐너를 호출하지 않고**(그 경로의 자기 warn 문구가 "스캐너 미호출 · 채널 미접촉" 을 스스로 인정한다) 종료하면서 heartbeat 를 기록해 **정확히 그 형상**이 됐다 — 관측을 0회 수행한 실행이 생존 신호를 남긴다.

⇒ 틀린 것은 근거가 아니라 **문면이 자기 근거보다 넓었던 것**이다. 문면을 근거에 맞춰 좁힌다.

### A1-2 정정 문면 (heartbeat 기록 조건)

**heartbeat 기록 조건** = "정상 종료" → **`collect_observations()` 가 실제로 호출되어 반환한 종료 경로**.

| 종료 경로 | heartbeat |
|---|---|
| 정지 (F1 ∨ F2 ∨ read-failure) | **기록하지 않는다** |
| `--dry-run` | **기록하지 않는다** |
| 관측 0건 · 채널 미지정 · 채널 조회 실패 · 신규 0건 · 정상 발화 | **기록한다** — 사이클을 완주했다 |

"관측 0건" · "채널 미지정" · "채널 조회 실패" · "신규 0건" 이 기록 대상인 이유는 **관측자가 살아서 한 바퀴를 돌았다는 사실이 그 네 경우에 모두 참**이기 때문이다. watchdog 이 겨냥하는 것은 "발화가 있었는가" 가 아니라 "관측자가 살아 있는가" 다.

### A1-3 대가 (declare — 은폐 금지)

1. **의도적 정지 중 소음** — 정지가 임계(기본 **172800초 = 2일**)를 넘기면 watchdog 이 **세션 시작마다** stderr 1줄을 발화한다. **"매일"이 아니라 "매 세션"** 이다(세션을 여러 번 여는 날에는 그만큼 반복된다).
2. **watchdog 은 "의도적 정지"와 "관측자 사망"을 구별하지 못한다.** 억제 수단은 `BYPASS_SCHEDULED_TASK_WATCHDOG=1` 뿐이고, **그 억제는 진짜 사망도 함께 가린다**. 이 미구별을 **결함이 아니라 선언된 상한**으로 받는다.
3. **구별 수단을 채택하지 않는다** — 구별하려면 정지 사실을 별도 상태로 기록하고 watchdog 이 그 상태로 분기해야 한다. 도입기 관측-only 에서 1번의 소음이 bounded 하고, 새 상태 파일은 §결정 4 **"신규 플래그 0건"** 정신과 §결정 6 **INV-OBS**(관측자는 자기 관측 도메인에 새 객체를 추가하지 않는다) 재검사를 요구한다. ⇒ **§결정 9 승격 게이트 재검토 대상으로 올린다.**

### A1-4 F1 소유권 declare (신규 — 종전 미기재)

**F1 = `.codeforge/post-merge-automation.disabled` 는 본 축 소유가 아니다.** 소유 = **ADR-026 §결정 4 + ADR-045 D-7**, 실 소비자 = `post-merge-followup.yml` · `retro-mandatory.yml`.

## Amendment 3 (CFP-2949, 2026-08-15) — Amd 2 판독 정의역을 **채택 표식 분기 도입 이후** 상태로 정정 + 실배선 상충 해소

### A3-1 — `:291` 정정: 판독 정의역은 "채택자 한정" 이 맞으나 `absent` 는 단일 case 가 아니다

Amd 2 는 **채택 표식 판별자가 도입되기 이전**에 쓰였다. 그 시점 배선에서 `absent` 는 분기 불가능한 단일 상태였고, 선택지는 *무조건 발화* 와 *무조건 침묵* 의 이지선다뿐이었다 — Amd 2 는 그 이지선다에서 후자를 택한 것이다.

**정정 문면 (Amd 2 `:291` 을 대체)**: 판독 정의역이 **채택자 한정**이라는 원칙은 **유지**한다. 단 채택 판정에 **표식 판별자**가 도입되어 `absent` 는 두 case 로 분화한다:

| heartbeat | 채택 표식 | 판정 | 발화 |
|---|---|---|---|
| `absent` | **부재** | 미채택 = 정상 (관측 대상 자체가 없음) | **무발화** |
| `absent` | **존재** | *"채택했는데 1회도 안 돌았다"* = 실 이상 | **발화** |
| `stale` / `invalid` | 검사 불요 | heartbeat 존재 = 최소 1회 실행 = 채택 증거 | **발화** |

⇒ Amd 2 의 *"`absent` 는 발화 사유가 아니다"* 는 **표식 부재 분기로 정의역이 좁혀진다.** 표식 존재 분기에서 그 문장은 **성립하지 않는다**.

원칙은 불변이다 — 억제 대상은 *"진짜 사망"* 이 아니라 **미채택(관측 대상의 부재)** 이며, 부재를 사망으로 읽는 것이 **관측 대상의 부재를 관측의 실패로 오분류**하는 것이라는 Amd 2 의 판정 논리는 그대로 유효하다.

### A3-2 — `:300` FN 방향 서술 정정

Amd 2 `:300` 은 본 결정을 *"false-negative 를 하나 늘리는 방향"* 으로 기술했다. 표식 판별자 도입 후 그 서술은 **틀리다** — 3-regime 대조:

**★ 단 이 명제는 조건부다 — 반례가 실재한다 (은폐 금지, A3-4 참조).**

1. **harm 모델 정합**: 본 축이 탐지하려는 harm(= 관측자 사망 · *"채택했는데 1회도 안 돌았다"*)은 **자기 치유하지 않고 지속**한다(A1-2 · A1-3 이 이미 기술한 성질). 지속하는 harm 은 유계 지연 탐지기로 잡히므로 **즉시성은 이 harm 이 요구하는 것보다 강한 요구**다. 반대로 100% 소음이 유도하는 **탐지자 자발적 폐기**(A1-3 항목 2 · A1-4)는 **무계 탐지 손실**이라 즉시 metric 을 고집한 대가가 metric 자신을 파괴한다.
2. **무계 종국 기각 — metric 이 완화 장치가 되는 것을 막는다**: 무계 종국은 *"언젠가는 잡힌다"* 로 **임의의 지연을 정당화**하는 데 재사용된다. `P=30` 을 정당화한 논리는 `P=30000` 도 똑같이 정당화하며, 그 경계를 metric 자신이 갖지 못한다. ⇒ **지연 상한 `D` 를 수치로 못박지 않은 종국 metric 은 채택하지 않는다.** 이 결박이 없으면 metric 고정이 완화 승인 절차로 전도된다.

★ **이 선택이 (ㄴ) 판정을 결정하는 방식 (은폐 금지)**: 유계 종국은 **P0 과 stateless-P4 를 둘 다 미충족으로 만든다** — P0 은 `D` 가 존재하지 않고(영구 무음), stateless-P4 는 기대값만 유한하고 **상한이 없다**(A5-3 tail 수치). 즉 본 metric 선택은 **본 Story 의 현행 판본에 불리한 방향**이며, 판정을 쉽게 만들지 않는다. 3회 연속 절차 비용을 낮추는 방향으로 틀린 이력이 있으므로 이 방향성을 명시 기재한다.

★★ **FIX10 자기 발현 추기 (위 ★★ 의 한 겹 위 — 은폐 금지)**: 위 문단이 *"오염면을 열거할 때 그 열거 자체를 실측으로 검증하라"* 를 처방했는데, **그 처방을 담은 표 자신이 정본 HEAD 에서 재현 불가**가 됐다. 게다가 직전 라운드(FIX9)가 「이 포인터의 천장」에 *"신규 인용은 절 ID"* 규칙을 세우면서 **기존 행번호 인용은 손대지 않는다**고 명시 유예했고, 하필 그 유예 대상 중 하나가 **본 항의 근거를 지탱하는 줄**이었다. ⇒ 규칙을 세우는 것과 **근거 지탱면에 소급 적용하는 것**은 별개이며, 유예의 정의역을 「근거 지탱 여부」로 자르지 않은 것이 직접 원인이다. 처분은 A5-7 이 규칙 자체를 좁히는 것이다.

★★ **신규 class 판정 — 「줄번호 포인터 stale」 (관계축 게이트의 미선언 사각)**: 본 결함은 그 게이트 정직 천장 ①~⑦ **어디의 발현도 아니다**. 판정 근거 = 그 모듈의 **절 ID 문법이 `A<n>-<m>` 와 `§결정 N` 두 형태뿐**이라(firsthand — `_correction_pointer_cochange.py` 의 `_SEC_ID_ALT`), **`:NNN` 행번호는 값 공간에 아예 없다** ⇒ 게이트는 이 좌표를 읽지도, 해소하지도, 위반으로 셀 수도 없다. ★ **직전 라운드와 판정이 다른 이유**: FIX9 의 「관련 파일」 결손은 인용 정의역(`## Amendment` 헤딩 사슬) **밖**이라 천장 ①·② 의 **발현**으로 귀속하는 것이 맞았다. 본 건은 정의역 **안**의 줄인데도 좌표 형태가 문법 밖이라 **구조적으로 안 보이는** 것이므로 발현이 아니라 **별 class** 다. 인접하되 disjoint 한 것은 천장 ⑤(`Amd 2` 같은 Amendment 레벨 지시자를 절 ID 로 세지 않음) 인데, ⑤ 는 *지목과 인용의 구분 불가*가 사유이고 본 class 는 *좌표가 시간에 따라 썩는다*가 사유라 **기전이 다르다**. ⇒ 천장 목록에 **⑧ 로 추가**되어야 한다.

★ **⑧ 의 SSOT 미착지 declare (정직 — 본 라운드가 못 한 것)**: 그 천장 목록의 SSOT 는 `tests/scripts/_correction_pointer_cochange.py` 모듈 docstring 인데, **본 라운드 정의역이 `tests/**` 무접촉**이라 거기에 쓰지 못했다. 본 라운드가 실제로 한 것은 **문서면 선언**(본 항 + 계획서 §9.5 행 24)까지이며, **SSOT docstring 의 ⑧ 등재는 미착지 잔여**다. *"천장에 추가했다"* 로 읽지 말 것 — 추가된 것은 문서면 선언이고 모듈 docstring 은 여전히 ①~⑦ 이다.

★ **FIX11 정정 — 위 미착지 declare 를 회수한다 (현재 시제로 거짓이 됐다)**: 위 문단은 **저작 시점에는 참**이었으나 지금은 아니다. 실측(ArchitectPL firsthand): `c2182d242` 가 위 declare 를 썼고, **같은 브랜치의 후속 커밋 `760cd77ef` 가 SSOT 등재를 착지**시켰다(`_correction_pointer_cochange.py` +18줄). 그 커밋은 **ADR 를 건드리지 않아** 선언만 옛 상태로 남았다. 현재 docstring 은 `L94` 에 ⑧ 본문, `L105`-`L107` 에 ⑤·⑦ 과의 기전 구분 및 완화 방향(저작 규율)을 담는다 ⇒ 모듈 docstring 은 **①~⑧** 이며 *"여전히 ①~⑦"* 은 **더 이상 참이 아니다**. 위 문면은 **삭제하지 않고 이력으로 보존**하며, 충돌 시 **본 추기가 우선**한다.

> ★ **이 건이 남기는 교훈 (설계리뷰 iter8 적발)**: 정직 declare 는 **착지보다 늦게 갱신되면 그 자체가 거짓 문장이 된다.** *"아직 못 했다"* 는 문장은 **시점 의존**이라 유통기한이 있고, 그것을 갱신하는 주체는 **착지시킨 커밋**이어야 한다. 착지 커밋이 선언면을 동반 갱신하지 않으면 문서는 **자기가 이미 한 일을 안 했다고 말한다** [ceiling: 본 교훈은 산문 규율이며 이를 강제하는 검사는 없다 — 아래 「기계 검사 표면 부재」 참조].

★ **기계 검사 표면 부재 (정직 기재)**: 본 정정을 정의역으로 삼는 오라클은 **없다**(A3-5 · A4-6 승계). 다만 위 표의 `grep` 행은 **재현 가능한 절차**이며, 이를 *"검사가 있다"* 로 격상해 읽지 말 것. ★ 관계축 co-change 게이트도 위 ⑧ 판정대로 **이 class 를 잡지 못한다**.

### A5-4 — P0 vs P4 **실평가** (A4-5 이분법 기각 — 중간점을 실제로 계산한다)

**불변 제약 (평가 전 고정)**: 도입기 = **관측-only · 삭제 0** · 계획서 `:405` **"신규 플래그 0건"** · §결정 6 **INV-OBS**(`:117` — *"관측자는 자기 관측 도메인에 새 객체를 추가하지 않는다"*). 이 제약을 푸는 것은 §결정 9 승격 게이트 사안이지 본 라운드 사안이 아니다.

#### A5-4-a — 무상태 P4 의 정체 = **확률적 종국**이지 결정론 `≤P` 아님

`P=30` 무상태 키잉에서 *"채택 + 표식 불가시"* 상태가 `N` 세션째까지 **무음**일 확률 = `(1 − 1/P)^N` = `(29/30)^N` (ArchitectAgent 직접 계산):

| 세션 수 `N` | 아직 무음일 확률 |
|---|---|
| 10 | **71.25%** |
| 30 (= 기대 첫 발화 세션) | **36.17%** |
| 60 | 13.08% |
| 90 | 4.73% |
| 200 | 0.114% |

⇒ **기대값은 유한(30 세션)하나 상한은 존재하지 않는다.** A5-1 이 고정한 **유계 종국**은 *"선언된 유한 상한 `D` 안에 **반드시**"* 를 요구하므로 **무상태 P4 는 (ㄴ) 를 충족하지 못한다** [bound: 무상태·확률 키잉 판본 한정 — 상태 보유 판본은 A5-4-c]. ★ **은폐 금지**: *"첫 발화 기대 세션 30"* 은 **기대값**이지 보장이 아니다. 이를 *"30 세션 안에 잡힌다"* 로 읽는 것은 위 표의 **36.17%** 를 지우는 것이다.

#### A5-4-b — 무상태 P4 의 **추가 대가 3종** (설계리뷰 제출 표에 없던 것 — 본 평가가 새로 계상)

1. **결정론 계약 파손**: §9.5 행 13 이 *"남는 통제는 **CLI 코드의 결정론**(§8 오라클)과 축소 불가한 상속 자격증명 scope 뿐"* 으로 적어 결정론은 **잔여 통제 2종 중 1종**이다(계획서 `결정론` **22 hit** — ArchitectPL 재실측, 계획서 정본 `30964c4a`. ★ FIX10 정정: 종전 기재 **21** 은 실측치와 1 어긋났고, 어긋남 자체는 본 항의 논거[결정론이 잔여 통제 2종 중 1종]에 영향을 주지 않는다). 난수 키잉은 그 통제를 **발화 축에서 소거**한다 — 오라클이 *"이 입력에 이 출력"* 을 잼지 못하고 분포만 잼게 된다.
2. **날짜 키잉 대안의 aliasing (확률 tail 보다 나쁜 class)**: 난수를 피해 `날짜 mod P` 로 결정론을 지키면 **세션 cadence 와 `P` 가 공약수를 가질 때 영구 무음**이 된다(예: 특정 요일에만 세션을 여는 운영자 ↔ `P` 가 7 의 배수). 확률적 tail 은 시간이 줄이지만 **aliasing 은 줄지 않는다** — 즉 결정론을 되찾는 대가가 **무계 FN class 신설**이다.
3. **§9.5 행 1 이 다시 거짓이 된다**: 행 1(*"다른 운영자는 merge 만으로 아무 **산출물**도 얻지 못한다"*)은 FIX6 착지로 비로소 참이 됐다. 무상태 P4 는 미채택자에게 3.3% 확률로 산출물을 주므로 **그 행을 다시 거짓으로 만든다.** 정합을 되찾으려면 행 1 을 완화 서술로 고쳐야 하고 그것은 **선언 하향** = (ㄴ) 가 금지하는 방향이다.

#### A5-4-c — 결정론 `≤P` 보장은 **상태 파일 1개**를 요구한다 ⇒ 승격 게이트 회부 (선례 인용·검증)

유계 종국을 **보장**하려면 *"마지막 발화 이후 경과 세션 수"* 를 어딘가 기록해야 한다 = **새 상태 객체 1개**. 이는 계획서 `:405` **"신규 플래그 0건"** 과 §결정 6 **INV-OBS** 재검사 대상이다.

★ **동형 선례가 본 ADR 안에 이미 있다 (firsthand 확인 — A1-3 항목 3, 인용문 앵커 = *"구별 수단을 채택하지 않는다"* 로 시작하는 항)** [ceiling: FIX10 재앵커 — 종전 `:275` 행번호는 후속 커밋 삽입으로 A1-1 헤딩을 가리키게 됐다]: *"구별하려면 정지 사실을 별도 상태로 기록하고 watchdog 이 그 상태로 분기해야 한다. 도입기 관측-only 에서 1번의 소음이 bounded 하고, 새 상태 파일은 §결정 4 「신규 플래그 0건」 정신과 §결정 6 INV-OBS 재검사를 요구한다 ⇒ **§결정 9 승격 게이트 재검토 대상으로 올린다**."* ⇒ 본 항은 그 선례와 **구조적으로 동일한 사안**(새 상태 파일로 watchdog 분기를 늘림)이므로 **같은 처분**을 적용한다.

#### A5-4-d — 처분 + **정직 declare 4항**

**도입기 처분 = P0 유지.** 단 **(ㄴ) 는 충족되지 않으며 그렇게 기록한다** — 본 처분은 *"(ㄴ) 를 만족시켰다"* 가 아니라 *"도입기 불변 제약 안에서 (ㄴ) 를 만족시키는 정책이 없고, 제약을 푸는 것은 승격 게이트 사안"* 이다.

1. **축·방향 라벨** — 손실은 **탐지 축 · 방향 = 채택자 무음**. 이미 `c3063d28c` 로 착지(hook 헤더 `(i)(ii)(iii)` 전건 `[탐지 축]` + *"진짜 채택자가 heartbeat 부재 상태일 때 pre-FIX6 은 발화했고 현행은 침묵한다"*, ArchitectAgent 확인).
2. **metric 명시** — 유계 종국(A5-1). 이 metric 에서 P0 은 `D` 가 **존재하지 않는다**(영구 무음).
3. ★★ **기각된 중간 후보와 그 실측 대가를 함께 기재** — 기각한 대안은 *"pre-FIX6 소음 100% 복원"* 이 **아니다**. 실제로 기각한 것은 **`P=30` 무상태 P4 = 미채택자 소음 3.3% · 첫 발화 기대 세션 30** 이며, **그 수치를 알고도 기각**했다. 기각 사유는 A5-4-a(상한 부재) + A5-4-b(결정론 파손 · aliasing · 행 1 거짓화) 3항이지 *"어차피 소음 복원이라서"* 가 아니다. **A4-5 의 이분법 문면 — *"없애려면 표식 부재 시 발화로 되돌려야 하고 그것은 pre-FIX6 소음의 복원이다"* — 은 이로써 기각된다** [ceiling: FIX10 재앵커 — 종전 `:453` 행번호는 후속 커밋 삽입으로 A4-3 구간을 가리키게 됐다].
4. ★ **P4 잔여도 은폐 금지** — P4 를 채택했더라도 남았을 것: 무음 확률 tail(A5-4-a 표, `N=90` 에서도 **4.73%**) · 날짜 키잉 시 aliasing · 미채택자 3.3% 소음. **P4 는 (ㄴ) 를 충족하는 선택지가 아니라 harm 노출을 줄이는 선택지**였고, 그 구별을 흐리지 않는다.

**승계**: **상태 보유 P4**(결정론 `≤P` 보장)를 **§결정 9 승격 게이트 재검토 대상**으로 올린다 — `:275` 선례와 동일 처분. 도입기에 배선하지 않으며, 본 문면이 그 착지를 **선언하지 않는다**.

### A6-1 — §결정 9 ⑧ 의 유예 트리거는 실 노출 창을 덮지 못한다 [판정]

⑧ 의 트리거 문면 = *"dedup 이 **관측 외 판단**에 쓰이기 전"*. 이 트리거는 **두 겹에서 어긋난다**.

1. **피해 발생면이 트리거 정의역 밖이다.** 억제의 1차 결과는 *"한 번도 보고된 적 없는 잔재"* 이고 이는 관측 **내부**에서 완결된다. 도입기는 정의상 관측-only 이므로 그 기간 내내 트리거가 발화하지 않는다 ⇒ **방어 부재 구간 = 결함 활성 구간 전체**. 유예의 대가가 유예 기간과 정확히 겹친다.
2. **⑧ 자신의 목적(승격 근거 보호)에 대해서도 한 단계 늦다.** ⑧ 은 승격 조건 ①(*"도입기 연속 운용에서 오보 0"*)의 근거로 도입기 기록을 쓰는 것을 트리거에 **포함**시킨다 — 즉 방어를 **판독 시점**에 건다. 그러나 오염은 **생성 시점**에 일어나고 채널은 append-only 라, 사후 배선은 이미 오염된 기록을 정화하지 못한다. 방어가 서야 하는 시점은 기록을 **읽기 전**이 아니라 **쌓기 전**이다. ⇒ ⑧ 은 자기 목적 기준으로도 순서가 한 칸 밀려 있었다.

**분류 정정 (본 판정의 핵심)**: T-SUP-1 은 *중복 제거(dedup)의 실패*가 아니라 **1차 탐지 false-negative** 다. 억제되는 대상은 *중복 보고*가 아니라 **아직 한 번도 보고되지 않은 잔재**이며, 이는 본 Story 가 닫으려는 ADR-169 observer-death false-negative 와 **같은 축에서 방향만 반대**다. 나아가 append-only 라 **영속**하고 억제가 일어났다는 신호가 산출 어디에도 남지 않는다. ⇒ 도입기 수용의 근거였던 *"관측-only 라 피해가 작다"* 는 성립하지 않는다 — **관측-only 시스템에서 관측 산출의 오염은 그 시스템이 입을 수 있는 최대 피해**이고, 삭제·상태변경이 없다는 사실은 피해를 줄이는 것이 아니라 **피해면이 관측 하나뿐임**을 뜻한다.

**처분**: ⑧ 의 **지위를 「승격 조건」에서 「도입기 선행 의무」로 승격**한다. §결정 9 의 8항 열거 문면은 삭제하지 않고 이력으로 보존하며, 충돌 시 본 Amendment 가 우선한다. 승격 게이트에서 ⑧ 이 사라지는 것이 아니라 **선행 시점이 앞당겨진다**(승격 시점에는 이미 배선된 상태여야 한다).

**sev 재판정**: 계획서 §7.2 T-SUP-1 **P2 → P1**. **P0 으로 올리지 않는 근거** = 로컬 상태 변경·파일 삭제·자격증명 노출이 따라오지 않으며, 오염 코멘트가 제거되면 상태 무의존 재관측이 자기치유한다. ★ 단 그 회복은 **오염의 발견을 전제**하고 **발견 경로는 아직 배선되지 않았다** — 이 조건을 빼고 "자동 회복된다" 로 읽으면 P1 근거가 무너진다.

2. **자기 저작 인용 잔여 (봉합이 닫지 못하는 것)**: **같은 자격증명**으로 저작된 코멘트가 SENTINEL 과 `· key=` 줄을 포함하면 여전히 채택된다. 운영자·에이전트가 같은 채널에서 보고 본문을 **인용**하면 그 인용이 억제로 작동한다 — CFP-2884 에서 방어 helper 가 자기 SENTINEL 을 인용한 PR 리뷰에 무력화된 사례와 **동형**이다. 완화 방향 = (ㄱ) 채널을 전용 Issue 로 고정하고 사람·에이전트 저작을 절차로 금지(**advisory**) (ㄴ) nonce/HMAC 승격(신규 상태를 요구 ⇒ 도입기 미채택, §결정 9 회부). **본 봉합의 정의역은 「타인 저작」이며 「자기 저작 인용」은 잔여로 남는다.**
3. **미인증·토큰 부재**: `viewerDidAuthor` 가 전부 false 로 와 dedup 이 공집합이 되고 전량 재발화한다(소음 방향).
4. **계정 탈취 시 무효** — 자격증명이 곧 신뢰 근거이므로 자명하나 기재한다.
5. **테스트 픽스처 동반 갱신 필요**: 기존 `gh` stub 픽스처가 이 필드를 갖지 않으므로 미갱신 시 dedup 이 공집합이 되어 **테스트가 RED 로 드러난다**(조용히 통과하지 않는다 — fail-safe 기본값의 부수 이득). 대표 갱신 대상 = `tests/integration/test_scheduled_task_ac_matrix.py` 의 AC-3 검증자.

**SENTINEL 을 남기는 이유**: 그것은 **형식 식별자**(우리 산출물 줄인가)이고 `viewerDidAuthor` 는 **저작 신뢰**(우리가 썼는가)다. 축이 달라 하나가 다른 하나를 대체하지 않으며, AND 로 결합할 때만 위조·오식별 두 축이 함께 닫힌다.

### A6-3 — 채널 **가시성**을 운영 파라미터로 신설하고 집행을 **실행 축**에 둔다 [결정]

**F-SEC-2 실측 (ArchitectPL firsthand 재현, `--dry-run` 34 항목)**: 보고 키에 `worktree:~\.claude\worktrees\<repo명>` · `temp:~\AppData\Local\Temp\claude\c--workspace-mclayer-<repo명>` 형태로 **repo 명이 그대로 실린다**. 그 중 `mcfleet` · `mctrader-data` · `mctrader-data-collector` · `codeforge-internal-docs` = **private**, `mctrader` = internal(gh api 실측). 동반 노출 = 파일수·용량(예: `files=179940 size=18631.0MB`) · 내부 브랜치 슬러그(`internal-docs-cfp-1806`).

**redaction 은 자기 정의역을 지킨다** — 사용자명·드라이브 문자·secret 리터럴은 제거된다. 그러나 **workspace 슬러그는 사용자명도 드라이브도 secret 패턴도 아니라 어떤 마스크에도 걸리지 않는다.** ⇒ AC-13 의 실패가 아니라 **분류표에 그 등급이 없던 것**이 결함이다.

**신설 파라미터 (§결정 6 표에 편입되는 지위)**

| 항목 | 값 | 근거 |
|---|---|---|
| **보고 채널 가시성** | **비공개 채널만 허용**(public repo Issue 를 채널로 쓰지 않는다) | 조직 topology(private repo 명부·규모)는 마스킹으로 제거할 수 없고, 제거하면 산출물의 쓸모가 함께 사라진다(A6-4). 채널을 옮기는 것이 유일하게 **내용을 훼손하지 않는** 통제다 |
| **집행 지점** | **CLI 실행 시점 preflight** — 발화 직전 채널 repo 가시성을 조회해 public 이면 **발화하지 않고 사유를 남긴다**(fail-closed) | 채널 값은 `--channel` / `SCHEDULED_TASK_CHANNEL` 로 **런타임에만 존재**해 PR·코드리뷰·CI 의 판독면에 도달하지 않는다. 문서 계약만 두면 **검사 주체가 없는 규범**이 된다 |

**등록 축 구조에 대한 판정 (요청된 핵심)**: 본 Story 는 §3.2 D3 에서 등록 축(schedule·folder·model·enabled·permission mode)을 *"git 재현 불가"* 로 선언하고 재현을 **문서화된 수기 절차**로 인정했다. 그 인정 자체는 유지한다 — 그러나 **그 인정이 보안 load-bearing 파라미터까지 덮은 것**이 F-SEC-2 를 가능하게 한 구조다. ⇒ **정정**: 등록 축 파라미터 중 **보안 결론을 지탱하는 값**은 수기 절차로 인정하지 않고, **그 값을 실제로 소비하는 실행 축에서 기계 검증**한다. 리뷰가 볼 수 없는 값을 리뷰로 지키려 하지 말고, **값을 쥔 프로세스에게 검사를 시킨다** — 이는 A6-2 가 저작 신뢰를 응답 자신에서 계산한 것과 **같은 이동**이다.

**대가 3항**: ① 조회 1회가 매 실행에 추가된다(Daily 주기라 예산 영향은 미미) ② 조회 실패 시 발화하지 않는 fail-closed 는 **기존 dedup 조회 실패 처분과 같은 형상**이라 새 실패 class 를 만들지 않으나, GitHub 불안정 구간에서 관측 침묵을 1 tick 늘린다 ③ 우회 env 를 둘 경우 그 사용은 audit 1줄을 남겨야 하며, **묵음 우회 경로를 만들면 본 결정이 무효**가 된다.

### A6-4 — repo 명 마스킹·해시는 기각한다 [결정]

**기각 근거**: 본 시스템 산출물의 쓸모는 *"어느 잔재가 어디에 있는가"* 이고, workspace 슬러그가 바로 그 **식별 payload** 다. 마스킹·해시는 dedup 축은 보존하지만(결정론 함수면 충분) **운영자가 대상을 특정할 수 없게** 만들어, T-SUP-2 처분이 *"경로가 `<제거>` 로 렌더돼 운영자가 잔재 위치를 특정 불가"* 를 **결함으로 판정한 바로 그 상태**를 자발적으로 재생산한다. ⇒ 같은 문서가 한 축에서 결함이라 부른 상태를 다른 축에서 처방으로 채택할 수 없다.

**대신** 민감 데이터 분류에 **조직 topology**(private repo 명·worktree 명·디렉터리 규모) 등급을 신설하고, 그 등급의 **유일한 통제는 채널 가시성**임을 명시한다(내용 축 통제는 성립하지 않는다). 이것이 A6-3 을 필수로 만드는 연결 고리다.

**도입기 무해 논거 재평가 (요청 3)**: **성립하지 않는다.** ① 무해 논거는 *로컬 쓰기 축*(삭제·상태변경 없음)을 재는데, 두 결함의 피해면은 *읽기·보고 축*이라 논거와 피해면이 서로 다른 축이다 ② F-SEC-2 와 결합하면 도입기에도 **매일 1회 실 손해(정보 공표)**가 발생하며 그 손해는 관측-only 로 줄어들지 않는다 ③ 공개 채널이라는 사실 자체가 F-SEC-1 의 공격자 집합을 **임의의 인증 계정**까지 최대화한다 — 즉 두 결함은 독립 사건이 아니라 한쪽이 다른 쪽의 노출을 키운다.

### A6-5 — 근인 판정 + 재사용 가능한 판별 질문

**근인**: 한 객체(보고 채널 Issue)가 **입력원 · 상태 저장소 · 출력 sink** 3역을 겸하는데, 신뢰 경계는 **입력 1역에만** 그려졌다. T-INJ-1 은 정교하게 다뤄졌고 INV-D(외부 본문 폐기)까지 배선됐지만, 같은 객체가 **dedup 상태의 실질 저장소**라는 reconcile 무상태 결정의 문장은 위협 분석과 연결되지 않았다 — 신뢰 밖 객체에 상태를 두면 **그 상태가 신뢰 밖**이라는 함의가 어디에도 전개되지 않았다.

**재사용 판별 질문**: *"이 객체는 몇 개의 역할을 겸하는가? 각 역할마다 경계를 그렸는가?"* — 한 역할에만 경계를 그리면 나머지 역할은 **경계가 있다는 착시 아래** 무결박으로 남는다. 본 Story 의 §7.1 다이어그램은 화살표가 외부→세션 1방향뿐이었고, 그래서 6 라운드 동안 어떤 리뷰도 채널의 나머지 두 역할을 묻지 않았다.

★ **기계 검사 표면**: 없다. 역할 열거의 완전성을 판정하는 오라클은 부재하고 검출 경로는 사람 리뷰였다(보안테스트 lane). *"이제 절차가 보장한다"* 로 격상해 읽지 말 것.

### A6-8 — 본 Amendment 의 정직 천장

- **본 Amendment 를 정의역으로 삼는 오라클 = 없다**(앞선 세 Amendment 가 같은 형식으로 남긴 선언을 승계한다). A6-2·A6-3 의 배선은 구현 lane 산출이며, 배선 전까지 두 결정은 **처방이지 통제가 아니다**.
- **A6-2 는 타인 저작만 닫는다** — 같은 자격증명의 자기 인용 억제는 대가 2항으로 남았고, 그 잔여를 잼는 검사도 아직 없다.

- 본 Amendment 의 신규 인용은 직전 Amendment 가 세운 규칙대로 절 ID 로 앵커했다. 행번호 인용을 새로 만들지 않았다.
